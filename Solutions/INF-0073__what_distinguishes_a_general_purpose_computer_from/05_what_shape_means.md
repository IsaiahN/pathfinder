## 1. A shape is a constraint, not a filler

The canonical figures README states the limit: the framework returns "what a missing thing would have to look like (a shape, not a name)." Fig 9 :32: "you get a kind of thing, never the answer itself." Fig 13 :133: "A system with a closure can answer that before it searches, and what it returns is a shape rather than a name."

From *The Library of Babel*: "This means that you can cut your search short if the set of books returned is small and descriptive enough that it provides a general shape of the answer that satisfies your question."

So a **shape** is the narrowed form of an answer you can state before you can name the instance. It constrains; it does not fill. For this question the shape is: **a union of a generator condition and a ground condition, with a withheld universal classifier.** Naming a particular CPU as the answer would be a name, not a shape.

## 2. How the shape is obtained

- *Library of Babel*: use the vocabulary you already have that is closest to the thing, then look for new terms that overlap or correlate with it. "With each new term gained, you narrow the space and deepen your vocabulary." This is a bootstrapping convergence process.
- Fig 6 :30: "The description travels. Fails by being sharpened into terms only we can read. Cast it in effect terms." Fig 9 :30-31: "your words are borrowed too, so describe the effect rather than the cause." Hence the question was restated in effect terms in `01` section 0: what changes if interpretation suffices versus if generation is required.
- *Decoding Tacit Knowledge*: "When contact isn't possible, the best you can send is a plain description of what you'd expect to see, because anyone can check that against the world." This is why the refuter in `02` is written as things you would expect to observe, not as a request to accept a theory.
- *Library of Babel* on stopping: "You will know that you are done because the finish line will also be the starting place, as there is nowhere else to search and nothing else that can describe the answer better." And the paradox: by the time you have the exact terms, "you have already composed the answer through the process of locating it."

## 3. The shape this question returns

The derivation in `01` narrows to two conditions and one limit.

1. **Generator condition.** A closed primitive set with unbounded arrangements, a program stored as data, and a method that can be reapplied. *How Intelligence Actually Works* describes the architecture this way: the kernel is fixed while the operating system grows, and "the intelligence, if it was going to exist, had to come from the architecture I was building," not from the trace.
2. **Ground condition.** An anchor that does not move when the observer changes the description. *Decoding Tacit Knowledge*: "Context, subtext and pretext decide what a message means to you. None of them decides whether it is true. Only the ground does that."
3. **The limit.** No universal classifier naming which physical systems compute. *How Intelligence Actually Works*: "The recursion converges toward indiscernibility, and indiscernibility is not identity. The projection that no instrument distinguishes from the thing is still a projection, which is why the lineage has to be kept even when the copy is perfect."

## 4. What licenses a name (with a correction to my own §3)

**Correction, kept visible.** I initially read "shape, not a name" as forbidding the naming of any separating property. That overstates the rule.

- The canonical phrase is about a **missing** primitive, one not held in Γ. The instruction set, the program, the ground and the bond are not missing from our vocabulary. We hold them.
- *They're Scanning Books*: "A minimum viable set of six terms is a human's careful guess at reality's compression axes; another sensorium's minimum set need not be those six." Also: "Declaring the primitives does not make them neutral. It makes the choice visible." A visible choice can be revised.
- Therefore naming the two conditions is a **binding** from the computation frame onto held loop and ground properties, provenanced as such. It is not the invention of a new primitive. What the framework still cannot name is *which physical systems* compute, because that needs a source-discriminating instrument. The correction does not remove the limit; it relocates it from the properties to the instances.

I keep both the earlier overstatement and the narrowed form here so neither is quietly lost.

## 5. Why trace, structure and metamerism matter here

*How Intelligence Actually Works* gives a thought experiment that lands directly on this question: a frame extracted from a video and a photograph taken at the same moment "are indistinguishable as artifacts, and they carry different warrants. One was taken; one was extracted. And nothing in the image records which." That is provenance loss. A rock under a mapping and a CPU running the same automaton have the same input-output artifact and different warrants, and nothing in the trace records which.

*The Hard Problem is About Source* sharpens it: "If several paths create the same behavior, then behavior is a projection with lossy information." An instrument that reads green "cannot comment on the source." And: "The answer is unreached until a better instrument exists." It was the spectrometer, not an argument, that resolved the case. So F8's gap is not a refusal to answer; it is a report that the discriminating instrument is not in hand. "Unreachable is a verdict here, not a silence" (Fig 13 :134).

*They're Scanning Books* adds the representation limit: "The invisibility is in the compression scheme, not the data." A source-discriminating instrument for computation would have to be able to register an implementation relation it has primitives to represent. That is why the gap is stated as an instrument requirement rather than as a request for more examples.

## 6. Two consequences for this package

**Prestige is not action.** *The Recursive Self-Improvement Trap*: "Prestige can fund an action. It can give an action a budget to be tried. But it cannot settle an action. Only the ground can settle it. The Ground Maintainer must be blind to prestige." The public contact list in `03` is therefore not ranked by likely agreement or by fame. A ground-visible record of contact with this residual is the selection criterion; receptiveness is excluded.

**This audit is a simulation, not a ground reading.** Same essay: "the output is only as good as the validator. The agent, or the tool, or the frame, or the theory, cannot validate itself." And: "the truly testable output would need to be derived from the real architecture or working the formula yourself." The architecture article is blunter: because the text and the figures were fed to a language model, "the outputs generated must be seen as simulacra." So `01`, `06`, `07`, `09` and `11` are simulated derivations checked for internal consistency against the figures. They are not a test of the separator and cannot settle it. Every one of those files says so in its mode line.
