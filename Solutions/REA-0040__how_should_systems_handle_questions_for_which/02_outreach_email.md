**Subject:** Check one claim about unanswered questions before you decide whether the protocol is worth reading

> Hi [name],
>
> I have one specific claim about how a system should answer a question for which no available evidence settles it. I am not asking you to read the framework first, and I am not asking you to agree. If the claim does not survive, there is nothing else to look at.
>
> **The claim (`general` on the shape, `specified` on the procedure, not `grounded`):** "no evidence" is not one condition but a union of at least three, and a system that collapses them into one word ("unknown") throws away the information that tells it what to do next. The three are: (1) the answer is in the system's closure and was not found, (2) no instrument currently returns anything that fails to resolve, so there is no edge to extend, (3) the premise is false, so what is owed is a refusal rather than an explanation. A defensible protocol first splits the union, then runs the cheapest check (more independent search at the same reach), then tests the two opposed routes separately (sharpen an existing instrument, or import a description from a frame whose closure differs), and reports a mode-labelled status with a refuter and a lineage.
>
> The figure-grounded reason for the first step is short: "Disagreements that do not shrink with effort, where each rule keeps working well on a different subset, are not one hard question but several well-formed ones. Split it rather than search." (Fig 9 :4-5) And the reason the status is an output, not a silence: "Unreachable is a verdict here, not a silence," (Fig 13 :134).
>
> **What I am not claiming:** that the system should always say something, that "unknown" is forbidden as a user-facing word, that more search eventually settles everything, or that importing a frame that always answers is a fix. A status that is honest about which condition fired, what would settle it, and what would reverse it is the deliverable. A name for the missing thing is not: "It cannot say which primitive is missing, because naming it would mean already holding it." (Fig 13 :134-135)
>
> **What would refute the claim, written before I sent this:**
> 1. A definite answer to an actually evidence-free question is settled by a ground that does not move when frames change (there was an anchor all along).
> 2. A frame's closure changes under repeated search with the same atoms, or sharpening an instrument answers whether another frame holds the term.
> 3. An instrument is built from a description alone, with no prior reading that fails to resolve.
> 4. A false premise is withdrawn without any negation operator, or a crowd of agreeing frames predicts the ground as well as an anchored instrument.
>
> If any one holds, I will withdraw or narrow the claim. A one-line "this fails because..." is more useful to me than agreement. If you would rather not engage, no reply is needed.
>
> **If it survives, and only then:** the sources are below. The figures, not my summary of them, are the authority.
> - Verbatim figure text with line numbers (local files in the project under `FRAMEWORK/reference/`): every `Fig N :line` quote above can be checked there.
> - Canonical usage rule (local): `FRAMEWORK/reference/FIGURES_README_canonical.md`.
> - Background on the distinction between reducible and irreducible uncertainty: https://arxiv.org/abs/1703.04977
> - Background on abstaining when in doubt: https://arxiv.org/abs/1705.08500
>
> **If you want to use the method:** the eight-step formula is in the figures folder. Run it on a problem you know well and can check against a ground. Write down what would refute your result *before* you run it, and state the mode of what you get. A reported failure is more useful to me than a reported success.

## Why this version is ordered this way

| the move | figure-grounded reason |
|---|---|
| Claim first, framework second | Fig 10 :52, "Bring a characterised residual, never the source." The recipient checks the claim without holding the framework's interior. |
| Do not ask for agreement | Fig 2 :35, "Alignment is triangulation, not negotiation. A mirror cannot correct you." |
| Pre-registered refuter | A falsifier written before the run is a design instrument. Six are in `01` §4; four are in the email for brevity. |
| Mode on the substantive claim | `THE_FORMULA.md`: "Mode. general · specified · grounded. State which." An "ought" is not `grounded`. |
| No "just say unknown" | Fig 13 :134, "Unreachable is a verdict here, not a silence." A bare status is a lossy condensation (F10). |
| Three conditions kept separate | Fig 9 :4-5 (split rather than search); Fig 8 :40-41 (different facts, different instructions). |
| Refusal before explanation | Fig 5 :53, "refuted: a term we hold is wrong; a term is owed that says so". |
| No request for trust or prestige | Prestige "can fund an action... but it cannot settle an action. Only the ground can settle it." (Recursive Self-Improvement Trap) |
| Offer the formula as a method | Fig 4 :22, "Only methods cross up. Only head starts come down." The generator can be given away without giving away an answer. |
| Ask users to state their own ground and refuter | `THE_FORMULA.md` "Direction": a frame cannot check the direction of its own question. |
