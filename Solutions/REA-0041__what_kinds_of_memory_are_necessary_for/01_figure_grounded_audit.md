## 0. The residual, in effect terms

Flexible intelligence is not "having a lot stored." In loop terms it is this: a system meets a new situation, its current library Γ predicts, the observation disagrees, and there is a residual `R` per object slot. Memory is whatever is carried across encounters so that the next residual is smaller than it would otherwise have been. The residual to be answered is therefore:

> What must be carried, and in what arrangement, so that a system's **reach** (what it can compose and bring to bear) grows to close a new residual, rather than merely its **store** growing?

Two failure modes are named in effect terms before any figure is chosen:

1. **The store grows, the reach does not.** The system accumulates occasion-records it cannot reuse. Fig 5 :72: *"a library that grows is not a reach that grows."*
2. **The channel decays.** The system still holds terms but has lost contact with what settles them. Fig 10 :24: *"the ground does not decay, the channel does."*

What an answer would look like is written down and bound as an ordinary term (README): a *small set of load-bearing memory functions, kept as separate quantities, ordered by dependency, named only as a shape until a ground discriminates.* This is the Direction discipline: *"make the sought-for shape an ORDINARY TERM"* (THE_FORMULA.md "Direction"), so the preference can accrue a residual like anything else.

## 1. Domain census (before choosing any figure line)

R by arity, symmetry and scale, then one line per domain with actors / currency / anchor. No nameable anchor means it is not a domain yet. Fig 9 :22 gives the description triple: *"arity · symmetry · scale."*

**R (the residual).** Arity: memory relates at least two encounters (a past contact and a present residual), and the residual is indexed per object slot. Symmetry: record versus reach are asymmetric, one monotone and one not; method versus occasion-record are asymmetric across the membrane. Scale: settling happens within one scale; methods cross scales with a lossy round trip.

| domain | actors | currency | anchor | question type |
|---|---|---|---|---|
| D1 The store / record | primitives, terms, Γ, closure | bits (description length, cost) | the ground pays for a term before it can be composed over | partition (what may enter the library) |
| D2 The reach / usable memory | settled molecules, bonds, methods | derivability, what can be composed now | the ground; reach can fall on refutation | partition (which held terms are currently reachable) |
| D3 The membrane / cross-scale memory | one agent, the population, methods, recordings | methods up, head starts down | the round-trip gap `R_T` (Fig 4 :30) | filter with direction, not a wall |
| D4 The channel / contact maintenance | maintainer seat, percepts, instruments, habitat | contact with the ground; channel decay | the ground, which does not decay (Fig 10 :24) | maintenance, a seat's office |
| D5 The dependency chain of learning | perception, vocabulary, objective, planning, carry | what each link produces for the next | the objective link, where chains usually break (Fig 3 :24–26) | ordered dependency (Fig 3 :20) |

**Partition or union.** D1 and D2 are a partition of *quantities* (monotone record versus revisable reach, Fig 6 :43). The five memory functions across D1–D5 are a **union of overlapping conditions**, not a list of separate kinds: one and the same stored term can be a record, settled, reachable, per-slot and carried. Fig 9 :54–55: *"And when the split lands on a union rather than a partition, unbundle before you search again."* *"A bundled problem is usually a union of overlapping conditions, not a list of separate ones."* So the memory kinds must be unbundled before searching for a checker; a single lever that clears one condition leaves the intersections standing.

**Order by dependency (Fig 3).** Store (D1) → settle → reach (D2) → carry across scales (D3) → maintain contact (D4). The carry link (Fig 3 :15) consumes perception, vocabulary and the objective; a link whose input never arrives cannot be diagnosed (Fig 3 :22). Memory organization is therefore downstream of having an objective, not a substitute for one.

**Strain test before conclusion.** I tried reading "record" as a state and "reach" as a structure under Fig 13's two-kind rule. That is a strain: record and reach differ by *monotonicity* (Fig 6 :43), not by state/structure kind, and Fig 13 governs the six substrate terms. Re-census returns them to their own domains. No governing line was chosen until after this re-census.

## 3. Findings

### F1 — The record and the reach are two different memories (decisive, triangulated)

Fig 6 :42–43:

> **"What is recorded only grows. What is reachable is derived, and it can fall."**
> **"So the closure and the reach are two quantities: one monotone, one not."**

Fig 5 :72: **"a library that grows is not a reach that grows."**

These are two figures with low overlap (Fig 6 is about closure and the wall; Fig 5 is about the mint pipeline), so the split is triangulated. The record is append-only; the reach is a derived quantity that must be recomputed from everything held. Flexible intelligence needs both, and conflating them is the named failure: a system that measures progress by terms minted is counting the denominator (THE_FORMULA.md step 8).

**Refuter:** show a system whose reachable set is identical to its stored set under every refutation, or demonstrate that counting stored terms is a sufficient measure of what it can bring to bear.

### F2 — Refutation adds memory and reduces reach; nothing is deleted (triangulated)

Fig 6 :42: *"A refutation adds a term that refuses; it removes nothing, and the reach falls because"* Fig 6 :43: *"something was added rather than because anything was deleted."* Fig 5 :55: **"Nothing leaves the library. What falls is the reach."**

This is what makes a revisable memory safe to compute: a term is reachable if derivable under everything held, so the fall follows from derivation rather than stipulation, and a refused term cannot cycle back without new growth. Fig 6 :46: *"A store that deleted instead would have neither property, and could not tell never-held from held-and-given-up."* The Operators table distinguishes ¬ (refusal of a claim) from − (absence of an operand): a memory with only subtraction can say what is missing and cannot say that a held belief is wrong.

**Refuter:** exhibit a store that deletes on correction and still distinguishes never-held from held-and-given-up without an external record.

### F3 — Method memory crosses scales; occasion-records do not (triangulated)

Fig 4 :22–26:

> **"Only methods cross up. Only head starts come down."**
> **"upward: a method that can be reapplied. Never the recording of a particular success."**
> **"A recording carried upward looks like knowledge and is a description of one occasion."**

Fig 10 :68: **"a generator crosses, an instance does not"** (different figure, low overlap). So the necessary kinds are not "episodic versus semantic" as a vocabulary choice; they are *generators (reapplicable methods)* versus *instances (descriptions of one occasion)*. Only the former travel between scales. Fig 4 :30 requires the round trip and the measured gap: *"So take the round trip and measure the gap. Without it you are navigating by dead reckoning: confident about a position nobody checked."*

**Refuter:** show an occasion-record carried upward that is reapplicable without loss, or a round trip whose gap is zero for a method that changed scale.

### F4 — Settled versus merely held: settling is necessary but not sufficient (triangulated)

Fig 5 :69: **"settling is necessary for a term to be composed over, and it is not sufficient."** Fig 5 :72: *"a library that grows is not a reach that grows."* Fig 12 :106: **"Nothing composes over what was never admitted as a part."**

A memory system needs a status bit that the ground has paid for a term, kept distinct from whether anything can currently compose over it. Fig 5 :70: *"A term is settled when the ground pays for it. A term is usable when something can compose over it. Those are two conditions and this figure names one."* The second condition is structural, not a matter of what was paid.

**Refuter:** show a term that composes over something never settled by the ground, or prove that settlement is sufficient for usability.

### F5 — Residual memory is per slot, never aggregated (single-source: Fig 1)

Fig 1 :19: **"The residual is indexed by object slot, not aggregated."** Fig 1 :22: **"Aggregating across slots is how a live signal disappears into an average."** Fig 1 :28: *"A system that averages across objects has thrown away the only signal that says where to look."*

Memory of what failed must be indexed by the object or slot that failed. A global "everything is fine" with one live slot is a legal state (Fig 1 :13). A compressed, averaged memory of performance destroys the very signal that tells the system where to aim next. Triangulation status: single-source within the figures (Fig 1 restated in THE_FORMULA.md step 1, high overlap, so not a second witness).

**Refuter:** show that a single global error average preserves the location of a live slot as well as a per-slot record does.

### F6 — The carry link is last in a dependency chain (single-source: Fig 3)

Fig 3 :15: **"name what worked, verify it, and carry it to the next problem"** — this is memory proper, and it is link 5. Fig 3 :20: **"The chain is ordered by dependency, not by importance."** Fig 3 :19: **"Optimising a link that already works cannot rescue one that does not."**

The middle links are vocabulary and objective: *"having terms for what a situation offers and being able to say what would count as progress... has neither [obvious failures nor tests]"* (Fig 3 :25–26), and Fig 3 :27: **"A link with no instrument is not a link that works. It is a link nobody has looked at."** So "organize memory" cannot begin with storage architecture; it begins with whether the system has terms for what affords and a stated objective. A reading of the carry link without those inputs is a reading of nothing (Fig 3 :22).

**Refuter:** show a system whose carry link improves while its objective link is unmeasured, and demonstrate the improvement is not a re-description of the same residual.

### F7 — The channel decays, so memory needs an active maintenance office (single-source: Fig 10)

Fig 10 :24: **"the ground does not decay, the channel does."** Fig 10 :25: **"stale percepts, dropped transients, saturated metrics, pooled readings"** Fig 10 :28: **"you have lost touch"** Fig 10 :29: **"→ keep the anchor reachable"**

A memory that only stores is insufficient; the route to what settles a stored term must be kept reachable. Failure appears as stale percepts and pooled readings, and the output is not a verdict but *"you have lost touch."* Fig 11 :40 (different figure, low overlap): **"An improvement that does not change contact changes nothing, however much it improves."** So part of "organizing memory" is a seat's office, not the loop's: Fig 4's ground does not decay and that is "a seat's office, not the loop's" (THE_FORMULA.md step 8).

**Refuter:** exhibit a memory improvement that changes the ground contact while leaving the channel untouched, or show channel decay is undetectable from inside.

### F8 — Settled memory becomes an atom at the next level (triangulated)

Fig 12 :104: **"A settled molecule becomes an atom for whatever composes over it."** Fig 12 :107: **"Settling compresses the description and not what it cost to establish."** Fig 4 :33–34 (different figure): *"there is no top and no infinite regress. The level a method lands on remakes it."*

Memory is hierarchical and level-relative, not flat. What was expensive to establish is compressed to a reappplicable atom, but the cost of establishing it is not carried in the compressed form; whether it must be paid again depends on whether the record crosses the boundary (Fig 12 :108–110). This is also the answer to "how should memory be organized": across two kinds in lockstep with lossy transforms, not as one flat store.

**Refuter:** show a settled term that cannot serve as an atom at any level, or a level where the cost of establishment is preserved in the compressed description.

### F9 — Provenance is part of the memory, not documentation (triangulated)

Fig 12 :130: **"A term carries the atoms it was built from and the bonds that joined them. That record is not documentation of the term. It is the term."** Fig 12 :129: *"the order is not recoverable from the artefact. It is recoverable from the lineage."* Fig 10 :62–63 (different figure): *"A ruling carries provenance like an atom. The residual it answered, the reasoning, the date, in a record the seats below can read."*

THE_FORMULA.md step 4 stamps each accepted term *"with origin and seq."* So memory organization must keep the lineage: which residual a term answered, from what atoms, in what order. Without it the system cannot answer the second question Fig 12 :132 separates: *"given the library as it stands, could this have been reached at all."*

**Refuter:** show a composed term whose route is recoverable from the artefact alone with no lineage, or a check of reachability that needs no record of origin.

### F10 — Capability is agent-and-habitat, so memory cannot be optimized in isolation (triangulated)

Fig 11 :39: **"capability is a property of agent-and-habitat, never of the agent alone."** Fig 11 :40: *"An improvement that does not change contact changes nothing."* Fig 11 :70: **"A test harness is a substituted habitat. Which is why a synthetic solve proves wiring and never capability."** Fig 2 :42 (different figure): **"Buy independence in proportion to the cost of being wrong."**

This governs what would count as evidence for a memory architecture: a benchmark is a substituted habitat, so a synthetic solve proves wiring, not capability. A memory system is made more capable only by changing contact with a ground, and independence is bought in proportion to the cost of being wrong. Fig 7 :13 adds *"agreement compounds, evidence does not"*: a larger memory of agreeing opinions is not a better memory.

**Refuter:** show an agent-only memory change that moves the ground, or a synthetic memory benchmark that establishes capability rather than wiring.

## 4. SEARCHED / INWARD / OUTWARD (kept distinct)

When no single line closes the residual, THE_FORMULA.md step 7 asks three questions, in this order.

- **SEARCHED (first, cheapest).** Is the needed memory already in the record, unfound? Fig 6 :49: *"more search at the same reach: is it in here and unfound? The closure does not change."* Here: most of what flexible intelligence needs is already in Γ; the failure is that the reachable subset is not recomputed or the lineage is not read. Distribute the search and keep searchers independent (Fig 6 :50).
- **INWARD.** Extend the instrument from one already returning something. Fig 6 :32: *"An instrument is not built from a description. It is improved from a worse instrument already returning something."* Here: sharpen the per-slot residual readout, not the storage capacity.
- **OUTWARD.** Import a frame whose closure predicts the shape, with source gate and shadow test (Fig 6 :12–13, Fig 8). Here: import a new *axis* of representation rather than a new term, per *The Hard Problem is About Source* (essay, read this session context via `05`): *"The real import is not a new term in the existing space. It is a new dimension of the space."*

Importing against a budget limit adds an atom that was not needed (Fig 6 :51–52), so OUTWARD is not the default.

## 5. Pre-registered refuter (written before the conclusion)

Required before outreach: Seat Map :287 (canonical field guide) — *"a falsifier written before the run is a design instrument, not only an honesty device."* The shape claim is refuted if any of the following holds:

1. **Store/reach collapse:** a system's reachable set is identical to its stored set under every refutation, or stored-term count is a sufficient measure of what it can bring to bear (breaks F1).
2. **Deletion works:** a memory that deletes on correction still distinguishes never-held from held-and-given-up without an external record (breaks F2).
3. **Recordings generalize:** an occasion-record carried upward is reapplicable without loss, or a cross-scale round trip has zero gap (breaks F3).
4. **Aggregation is lossless:** a global error average preserves the location of a live slot as well as a per-slot record (breaks F5).
5. **Isolation improves memory:** an agent-only memory change moves the ground, or a synthetic benchmark establishes capability rather than wiring (breaks F10).

If any fires, the shape is withdrawn. Until one is run, no part of this may be labelled `grounded`.

## 6. Recommendation

1. Lead with F1 and F3: separate the monotone record from the revisable reach, and store methods rather than occasion-records.
2. Keep F2's refusal operator; a taxonomy with only subtraction can only accumulate.
3. Index residual memory per slot (F5), and do not begin with storage architecture before the objective link is instrumented (F6).
4. Treat channel maintenance as a seat's office (F7) and judge memory changes by contact, not by benchmark solves (F10).
5. Send the generator (the derivation, the shape and the refuter), not the conclusion. Fig 4 :25: *"A recording carried upward looks like knowledge and is a description of one occasion."*
