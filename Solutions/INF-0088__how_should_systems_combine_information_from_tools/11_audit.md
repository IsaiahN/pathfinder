## Round trip gap R_T

The Symbols table defines R_T as the gap between what was sent up and what came back down, `gap(x, (T_E composed with T_A)(x))`, measuring what the coarser description cannot hold. Fig 4 :30 requires it to be measured rather than assumed. I ran the round trip on the condensation the folder actually uses.

2. **Abstraction (T_A):** the shorthand carried in `07` and `08`: keep residuals per slot, infer source relation, range against ground, fuse redundant readings, refuse, record provenance, order by dependency.
3. **Concretisation (T_E):** a concrete system with three sources, a desired accuracy, a latency budget and a user-feedback channel.

**R_T is nonzero.** Four things the shorthand holds do not survive the trip back down:

- the **numeric weights**, which the shorthand deliberately leaves open and a concrete system must fill in;
- the **operational test for common cause**, which the figures name as a requirement but do not specify as a statistic;
- the **exact refusal criterion**, that is, when a source has become false rather than merely noisy;
- the **route-grade decision** about whether user feedback is an anchor or an instrument for the particular question being asked.

Conversely, one thing survives cleanly: the sources must be kept distinct, ranged separately, and fused only after a common-cause check, with provenance and a refusal. That is the residue worth sending. R_T was **not** measured numerically, because no ground experiment was run; it is recorded qualitatively as the enumerated set of dropped constraints. Treating the formula as identical to the metalaws would set R_T to zero and would be the dead-reckoning error Fig 4 :30 names. The honest form is a lossy condensation with a recorded gap, which is what `09_watson_answer.md` states.
