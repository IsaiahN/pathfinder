**Subject:** Check one output about memory before you decide whether the theory is worth reading

> Hi [name],
>
> I have one specific output I would like you to check against what you already know. I am not asking you to read the theory first, and I am not asking you to agree with it. If the output does not survive, there is nothing else to look at.
>
> **The problem in effect terms.** A system holds terms in a library. Some are stable knowledge: a rule it can re-apply and build on. Some are temporary facts: a record of one occasion that paid once. Some are context-specific assumptions: true only inside one frame. The hard part is that all three look identical in the stored artifact. A record of one occasion *looks like* knowledge. So the question is not what is stored but what a system is entitled to *do* with what it stores.
>
> **The output (`specified`, not `grounded`).** A single stability flag is the wrong object. The figures require four separate instruments, with verdicts kept per item and never averaged:
>
> 1. **Ground settlement.** Did the ground actually pay for this term? Settlement is necessary but not sufficient: a term can be paid for and still not be composable over.
> 2. **Method versus recording.** Can the term be re-applied in a new situation, or is it a replay of one success? A recording carried upward looks like knowledge and is a description of one occasion.
> 3. **Round trip.** Abstract the term to a rule, bring it back into a concrete case, and measure the gap. A stable abstraction has a small *measured* gap; assuming the gap is zero is dead reckoning.
> 4. **Provenance and closure.** Record where the term came from and which frame it was derived in. A convergent derivation and an adopted assumption look identical in their contents; only the record separates them.
>
> This is a shape, not a score and not a cutoff. The framework returns a kind of thing, never the answer itself, and I am not claiming it names the number of contexts or the length of time that would make a term stable.
>
> **What I am not claiming:** that this is a completed memory architecture, that it is implemented, that it settles the philosophy of knowledge, or that a list of agreeable experts would make it true. I am not claiming a stability flag can be read off a term's content. I am not asking for trust.
>
> **What would refute it (written before sending):**
> 1. A term settled by the ground and composable over, which later produces a novel success in a new situation with no re-application test.
> 2. A stability certificate that changes when the checking frame changes while the ground measurement stays fixed.
> 3. A recording of one occasion that survives the round trip with zero gap and is later shown to have lost information in the abstraction.
> 4. Two checkers with demonstrably disjoint evidence who agree a term is stable while the ground returns an error that persists and does not trend down.
>
> If any one holds, the shape is wrong and I will retract it. A one-line "this fails because..." is more useful to me than agreement. If you would rather not engage, no reply is needed.
>
> **If it survives, and only then:** the sources are below. The figures are the authority, not my summary of them.
> - Canonical figures text with line numbers (local): `FRAMEWORK/reference/03-FIGURES_TEXT.md`
> - Canonical usage rule (local): `FRAMEWORK/reference/FIGURES_README_canonical.md`
> - Public figures repository, branch `general-agent`: https://github.com/IsaiahN/tether/tree/general-agent/figures
>
> **If you want to use the machinery:** the formula is in the figures link. Run it on a memory problem you know well and can check against a ground. Write down what would refute your result *before* you run it, state the mode of what you get, and keep verdicts per slot. A reported failure is more useful to me than a reported success.
>
> - Isaiah
