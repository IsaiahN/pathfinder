## Round trip gap R_T

The Symbols table defines R_T as the gap between what was sent up and what came back down, `gap(x, (T_E ∘ T_A)(x))`, measuring what the coarser description cannot hold. Fig 4 :30 requires it to be measured rather than assumed. I ran the round trip on the condensation the folder actually uses.

2. **Abstraction (T_A):** the shorthand carried in `07`: the adaptive channel is a frame; reliability needs an unreadable resource; report per slot; refuse before mint.
3. **Concretisation (T_E):** a specific engineering recommendation, for example "use a 4096-bit key with a rate 1/2 code and a standard authenticated channel."

**R_T is nonzero.** Four things the shorthand holds do not survive the trip back down:

- the **identity of the resource**, which Fig 9 :32 says is a kind of thing, not an answer;
- the **truth of the overlap claim for a given deployment**, which needs a declared independence statistic, not the qualitative "adapts to the code";
- the **worst-case operand type for ⋛**, which the Operators table restricts to two quantities;
- the **gates on the import**, source provenance and a shadow test, which a casual "standard authenticated channel" skips.

Conversely, two things survive cleanly: reliability must be reported per slot at a separate receiver counter, and a channel that updates on the code fails the anchor test. That is the residue worth sending. R_T was not measured numerically, because no ground reading exists; it is recorded qualitatively as the enumerated set of dropped constraints. Treating "the formula is the condensed version of the metalaws" as identity would set R_T to zero, which is the dead-reckoning error Fig 4 :30 names.
