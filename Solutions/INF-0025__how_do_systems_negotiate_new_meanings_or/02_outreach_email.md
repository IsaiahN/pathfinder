# Outreach draft: validate the output first, then decide about the theory

**Use:** one-to-one, or as a cover letter attached to a submission through the public venues in `03_public_contact_points.csv`. **Not** for bulk send.

**Hard precondition:** do not send until the two-part split in `01_figure_grounded_audit.md` F1 and F5 is kept intact. If the convention claim and the verdict claim are blended in the first paragraph, the two-stage offer collapses on contact.

---

**Subject:** Check one prediction about how a first protocol gets off the ground

> Hi [name],
>
> I have one specific output I would like you to check against what you already know about protocol emergence. I am not asking you to read the framework first, and I am not asking you to agree with it. If the output does not survive, there is nothing else to look at.
>
> **The residual.** Two systems need a shared code in order to coordinate, but any negotiation of a code seems to presuppose a code in which to negotiate. The question is what settles the first shared term when no code precedes it. I am treating that as a union of two different things, not one hard problem: a convention (where agreement is the product) and a verdict about a ground (where agreement is not a witness).
>
> **The output (`general` shape, `specified` for protocols, not `grounded`).** The framework's answer is that the first code is not agreed into existence. It is found at a contact neither system authored, built from terms enumerated off shared regularities and hard-to-fake signals, installed as a convention that can be violated, and carried across when one system meets another whose vocabulary differs. The specific first code is not named. The framework returns a shape, not a name. What it offers is the shape any candidate first code must have, written in advance.
>
> **What I am not claiming:** that a shared symbol is a shared meaning. The relation between the terms carries information the terms alone do not, so identical inventories under different arrangements are different codes. I also am not claiming that repeated interaction certifies a code. Repetition stabilizes a convention; it does not make it track anything.
>
> **What would refute the shape claim, written before this email:**
> 1. two systems with no shared anchor and no contact with a differing vocabulary reliably converge on a stable shared code across independent pairs;
> 2. a stable protocol's first terms are demonstrably uninfluenced by any shared contact;
> 3. identical inventories under different arrangements produce no behavioural difference anywhere with adequate instrumentation;
> 4. a convention that decides a world-verdict is still counted as a convention;
> 5. a system reliably recognizes a correct first code with no prior written characterization of what a code would look like.
>
> If any one holds, I withdraw the shape and redo the census. A one-line "this fails because..." is more useful to me than agreement. If you would rather not engage, no reply is needed.
>
> **If it survives, and only then:** the sources are below. The figures are the authority, not my summary of them.
> - Figures and formula, public repository branch `general-agent`: https://github.com/IsaiahN/tether/tree/general-agent/figures
> - Worked architecture essay: https://medium.com/@IsaiahNwukor/arrival-of-the-fittest-the-tether-architecture-1de7edf641ec
> - Canonical usage rule: https://github.com/IsaiahN/tether/blob/general-agent/figures/README.md
>
> **If you want to use the machinery:** the formula is in the figures link. Run it on a protocol you know well and can check against a ground. Write down what would refute your result *before* you run it, and label the mode of what you get. The framework's own rule is that a loop cannot check the direction of its own question. A reported failure is more useful to me than a reported success.
>
> With thanks for your time,
> [your name]

## Stage discipline

1. **Stage 1.** Send the residual, the shape claim and the five refuters. Ask what the recipient would count as a failure. Record their verdict before any theory is shown.
2. **Stage 2, opt-in only.** If curious, offer the three links. The figures, not the summary, are the authority.
3. **Stage 3, opt-in only.** Offer the formula as a method. Each user writes their own refuter and states their own mode.

A stage-2 agreement is never pooled as corroboration (Fig 2 :40). A failure is copied into `11_audit.md` with provenance and re-evaluated by the auditor seat as if it came from any other source.
