**Use:** one-to-one, or as a cover letter attached to a submission through the public venues in `03_public_contact_points.csv`. **Not** for bulk send.

**Hard precondition:** do not send until the shape claim in `01_figure_grounded_audit.md` is checked against its three checkable sub-claims in `08_expert_verification_packet.md`. The output must survive validation or the two-stage offer collapses on contact.

**Subject:** Check one output before you decide whether the genetic-code claim is worth reading

> Hi [name],
>
> I have one specific output I would like you to check against what you already know. I am not asking you to read a theory first, and I am not asking you to agree with anything. If the output does not survive, there is nothing else to look at.
>
> **The output (`specified`, not `grounded`):** the modern genetic code is best described as a *settled convention over a closed set of parts*. Three things follow, and each is checkable on its own:
> 1. The parts (four bases, twenty amino acids, the translation components) form a **closed set**, but the possible arrangements over that set are **not** closed. Alternative codes are therefore *isomers*: same atoms, different arrangement, different resulting proteome.
> 2. The code is a **bond**, not an ingredient list. The same twenty amino acids under a different codon assignment are a different substance, exactly as two chemical compounds with the same formula can differ.
> 3. The near-universality of the code is a **handoff chain**, not evidence that this code is the best one. Agreement compounds down a lineage of common descent; evidence does not.
>
> **What I am not claiming:** that the code is a pure frozen accident, that it is a unique ground-driven optimum, that stereochemical affinity alone fixes the assignments, or that the framework can name which codon got which amino acid historically. The framework returns a shape, not a name. The historical assignment stays open until a ground settles it.
>
> **What would refute the shape claim:**
> 1. a workable code that requires a genuinely new molecular kind, so it is an import rather than a rearrangement of the held set;
> 2. all assignments shown fitness-equivalent (pure convention) **or** exactly one assignment shown viable (arrangement space collapses);
> 3. universality shown to arise by independent convergence of multiple origins with different closures onto the identical assignment;
> 4. a figure re-census that names a specific codon-amino-acid assignment;
> 5. a demonstrated directed maintainer of the primordial code.
>
> I wrote these down before sending this. If any holds, I retract the claim. A one-line "this fails because..." is more useful to me than agreement. If you would rather not engage, no reply is needed.
>
> **If it survives, and only then:** the sources are below. The figures are the authority, not my summary of them.
> - Verbatim figure text with line numbers (local): `FRAMEWORK/reference/03-FIGURES_TEXT.md`
> - Canonical usage rule (local): `FRAMEWORK/reference/FIGURES_README_canonical.md`
> - The eight-step loop and mode rule (local): `FRAMEWORK/figures/THE_FORMULA.md`
>
> **If you want to use the machinery:** the formula is in the figures link. Run it on a problem you know well and can check against a ground. Write down what would refute your result *before* you run it. The framework's own rule is that a loop cannot check the direction of its own question. A reported failure is more useful to me than a reported success.
>
> Thanks,
> [name]
