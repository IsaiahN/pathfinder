# Outreach draft: check one separator before you decide about the framework

**Use:** one to one, or as a cover note attached to a submission through the public venues in `03_public_contact_points.csv`. **Not** for bulk send.

**Hard precondition:** do not send until the fixed-final-set condition in the stage-1 question below is clear. If the recipient cannot hold final species identity constant while varying order, the check is not the one this packet asks for.

---

**Subject:** One checkable separator about extinction order, before any theory

> Hi [name],
>
> I have one specific output I would like you to check against your own work. I am not asking you to read a theory first, and I am not asking you to agree with anything. If the output does not survive, there is nothing else to look at.
>
> **The output (`specified`, not `grounded`).** Whether the order in which species disappear matters is a question about the type of bond joining the removals. Under a symmetric bond, swapping two removals changes nothing, and all k! orders over the same final set are one outcome. Under an ordered bond, swapping them changes the thing, and the orders are different outcomes. The figures give the operational test: swap the operands and ask whether the meaning changes.
>
> A second part of the same output: the final species list is an artifact, not the route. Two communities that end with the same species set can differ in functioning and stability because the route is part of the result. A survey that records only final richness has discarded the variable the question asks about. The route is recoverable only from the lineage: dated removals, intermediate states, secondary extinctions, and function readings at each step.
>
> **What I am not claiming.** I am not claiming that order matters in every ecosystem. Where species are functionally interchangeable at fixed richness, the bond is symmetric and order washes out. I am not claiming a universal worst order, a threshold number of removals, or that this settles any conservation priority. The framework returns a separator, not a ranking.
>
> **What would refute the output:**
> 1. In a dependency-structured community, every permutation of the same removal set gives the same measured function and stability at the same remaining set.
> 2. Final species identities plus final interaction strengths predict every function with zero residual attributable to route.
> 3. Two communities with the same remaining atoms and different recorded routes have identical measured behaviour on every function.
> 4. Removing a dependency base before its dependent produces the same intermediate trajectory as the reverse order.
>
> I wrote these down before sending this. If any one holds, the corresponding part is withdrawn. A one-line "this fails because..." is more useful to me than agreement. If you would rather not engage, no reply is needed.
>
> **If it survives, and only then:** the sources are below. The figures are the authority, not my summary of them.
> - Figures and formula, branch `general-agent`: https://github.com/IsaiahN/tether/tree/general-agent/figures
> - Canonical usage rule: https://github.com/IsaiahN/tether/blob/general-agent/figures/README.md

>
> **If you want to use the machinery:** the formula is in the figures link. Run it on a problem you know well and can check against a ground. Write down what would refute your result *before* you run it. A reported failure is more useful to me than a reported success.

## Two-stage discipline

**Stage 1.** Send only the residual, the separator, the lineage requirement and the four refuters. Ask what they would expect to see if the separator were true, and what they would count as a failure. Record their verdict before showing any theory.

**Stage 2, opt-in only.** If they are curious, send the three links. Their agreement after seeing the framework is never pooled as corroboration: Fig 2 :40 says agreement from a shared evidence pool is worthless for a verdict, and a recipient who has absorbed the framework has joined the frame being checked.

**Stage 3.** Offer the formula as a method to reuse, with the instruction that each user names their own ground and writes their own refuter before running it.
