# Outreach draft : check the shape before you decide about the framework

**Use:** one-to-one, or as a cover letter attached to a submission through the public venues in `03_public_contact_points.csv`. **Not** for bulk send.

**Hard precondition:** send only after the seven refuter conditions in `01_figure_grounded_audit.md` §4 are understood. The recipient must be able to try to break the shape without first absorbing the theory.

---

**Subject:** One checkable claim about agents that change, and what would break it

> Hi [name],
>
> I have one specific output I would like you to check against what you already know about agent-based modeling. I am not asking you to read a theory first, and I am not asking you to agree. If the output does not survive, there is nothing else to look at.
>
> **The question I started with:** how should a model represent agents whose rules, goals or access to information differ across time and context?
>
> **The output (`specified`, not `grounded`, and one part is a declared `gap`):** four requirements and one refusal.
>
> 1. Keep the residual indexed per agent and per step. A population average can sit near zero while one agent's slot carries all the signal, so a pooled or representative-agent score is not a coarser version of the truth, it is the operation that discards the only thing that says where to look.
> 2. Store the agent's signature, not a type label. A rule is an ordered relation (what follows what), a goal is a threshold comparison, an information limit is the absence of an operand, and a rule being replaced is a refusal of a claim. These are different operator kinds, and a flat ingredient list cannot tell them apart.
> 3. When the context changes, carry a reapplicable method rather than a recording of the rule that worked last time, and measure what the compression dropped.
> 4. Re-enumerate which agents matter for each new residual. A fixed importance list does not survive a change in what the model is trying to explain.
> 5. **What I do not claim:** the representation can tell you which rule is actually live at a slot. Several rule histories can produce the same observed behavior, so outputs alone cannot discriminate the source. I report that as `gap`, an instrument owed, not as silence and not as a name.
>
> **What would refute it:**
> 1. a pooled representation that preserves every per-slot signal and still pays at the ground after an independent agent-level intervention;
> 2. opaque type identifiers that survive an agent-swap ground test as well as a typed signature does;
> 3. a fixed rule set that keeps paying at the ground across a pre-registered context shift;
> 4. a fixed importance list that survives a change of residual;
> 5. a flat, bond-free representation that can write a route, a threshold, an absence and a refusal, pays at the ground, and costs less to state;
> 6. a single scalar that legitimately trades description cost against ground-check cost and predicts both;
> 7. an instrument that identifies the live rule from behavior alone, or a framework rule that does it, which would collapse the gap.
>
> I wrote these down before sending this. If any one holds, the corresponding requirement is withdrawn. A one-line "this fails because..." is more useful to me than agreement. If you would rather not engage, no reply is needed.
>
> **If it survives, and only then:** the sources are below. The figures, not my summary of them, are the authority.
>
> **If you want to use the method:** the formula and the figures are in the links. Run them on a model you know well and can check against a real system. Write down what would refute your result *before* you run it, and state whether your claim is `general`, `specified` or `grounded`. A reported failure is more useful to me than a reported success.
>
> Thanks,
> [name]

## Two-stage offer, explicit

- **Stage 1:** send the shape and the refuter. Record the recipient's verdict before showing any framework material.
- **Stage 2, opt-in only:** if curious, offer the source links. The figures are the authority, not the summary.
- **Stage 3:** offer the formula as a method to reuse, with the instruction that each user writes their own refuter and states their own mode.

A later agreement is never pooled as corroboration (Fig 2 :40 "disqualifying for a verdict: agreement about the world is worthless when the agreeing frames share an evidence pool"). A Track B style reply, if one ever occurs, is a conversation, never a witness.

## One-to-one rule

No bulk send, no automation, no misleading subject line, and an opt-out line in every message. GDPR and CAN-SPAM style rules apply to unsolicited outreach in many jurisdictions. Use the public submission and opt-in channels in `03_public_contact_points.csv` rather than personal addresses.
