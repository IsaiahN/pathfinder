## 3. Distribution: offer, do not push

Figure-grounded rules:

- **Fig 10 :42**, *"A verifier that can reconstruct the claim cannot verify it."* Send the residual and the refuter first. A recipient who has absorbed the entire framework before being asked for a check has joined the frame being checked.
- **Fig 9 :27-28**, *"describe it before you go looking, or any frame you pick will seem to fit."* Ask what the recipient would expect to see if the three claims were true before giving them the figures.
- **Fig 2 :35**, *"Alignment is triangulation, not negotiation. A mirror cannot correct you."* Do not ask for agreement. Ask what would count as a failure.
- **Fig 2 :40**, agreement among frames sharing an evidence pool is the pool talking. Record a Stage 1 verdict before any theory is shown; never pool a later agreement as corroboration.
- **Fig 4 :22-25**, only methods cross up, only head starts come down. A link to the full architecture sent before a residual is described is a recording, not a generator.
- **Fig 9 :60**, use filters for the budget and witnesses for the verdict. A venue's prestige is a contact-cost estimate, never an evidence score.

**Recommended order in a reply:** (1) the residual and the three checkable claims; (2) the pre-registered refuter and the question "what would you count as a failure?"; (3) record the verdict; (4) only then the three framework links, with the note that the figures, not this summary, are the authority.

## 4. The two-stage offer

1. **Stage 1:** send the residual, the shape claim and the refuter. Ask for a failure, not an endorsement. Record the answer before showing any theory.
2. **Stage 2, opt-in only:** if the recipient is curious, offer the figures link, the canonical README and the MDL article. A Stage 2 agreement is not corroboration.
3. **Stage 3:** offer the formula as a method to reuse, with the instruction to write a new refuter and state a mode for each new problem.

**Hard precondition:** stages 1 to 3 only work if the stage 1 output survives. Run the 20-minute check in `08_expert_verification_packet.md` yourself before sending. If it fails, repair or retract rather than recruit agreement.
