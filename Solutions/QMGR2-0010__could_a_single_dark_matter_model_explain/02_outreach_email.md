**Use:** one-to-one, or as a cover letter attached to a submission through the public venues in `03_public_contact_points.csv`. **Not** for bulk send.

**Hard precondition:** do not send until the four slots are stated separately and the pre-registered refuter in section 4 of `01_figure_grounded_audit.md` is attached. The output must survive validation or the two-stage offer collapses on contact.

**Subject:** Check one output about dark matter before you decide whether the framing is worth reading

> Hi [name],
>
> I have one specific output I would like you to check against what you already know. I am not asking you to read the theory first, and I am not asking you to agree with it. If the output does not survive, there is nothing else to look at.
>
> **The output (`general` on the shape, `specified` on the per-slot framing, not `grounded`):** the question "could a single dark-matter model explain galaxies, clusters, gravitational lensing, and the early universe?" bundles four different measurements into one yes/no. The framework's rule is that a residual is indexed by object slot, not aggregated. So I am asking the question as four residuals, each with its own anchor that does not change when a model proposes an answer:
>
> 1. galaxies: rotation curves and inner density profiles;
> 2. clusters: mass from kinematics, X-ray and Sunyaev-Zel'dovich;
> 3. lensing: convergence and image geometry, for example the Bullet Cluster mass-gas separation;
> 4. early universe: CMB acoustic peak locations and BBN light-element abundances.
>
> These are not symmetric instances of one thing. They sit on a dependency chain, with the early universe upstream because the CMB fixes the cold dark matter density and the initial perturbations the other slots inherit. The claim I am offering is a shape, not a model: any candidate that claims to be a single explanation must be a closure that reaches all four slots, must name an anchor at each, must say what it imports when a slot fails, and must carry a refuter per slot. The framework returns a kind of thing, never the answer itself, so it does not name a particle, a fluid or a model. Which model is correct is a gap I am recording as a gap, not a silence.
>
> **What I am not claiming:** that the figures say dark matter is impossible, that one model cannot work, or that any named candidate (CDM, warm, self-interacting, unified fluid) is selected. I am not claiming the small-scale tensions falsify a model outright: baryonic physics is in contact with the galaxy residual, so that slot is a union of conditions. Agreement among models fitted to the same dataset is one evidence pool talking, not corroboration.
>
> **What would refute the shape claim, written before sending:**
> 1. one closure is demonstrated to settle all four per-slot residuals at once against independent non-updating anchors, with no imported atom unaccounted for;
> 2. one of the four slots has no nameable anchor, so it is not a domain yet;
> 3. the four slots form a partition with one common atom and no overlap, so unbundling is unnecessary;
> 4. a figure line is found that governs which specific dark-matter model is correct;
> 5. the dependency order is shown to run galaxies-first, so the CMB is downstream.
>
> If any one holds, the framing is wrong and I will retract it. A one-line "this fails because..." is more useful to me than agreement. If you would rather not engage, no reply is needed.
>
> **If it survives, and only then:** the sources are below. The figures are the authority, not my summary of them.
> - Canonical figures text with line numbers (local): `FRAMEWORK/reference/03-FIGURES_TEXT.md`
> - Canonical figures README usage rule: https://github.com/IsaiahN/tether/blob/general-agent/figures/README.md
> - The eight essays and the architecture, for how "shape" is defined: https://adventuresinml.substack.com/p/how-intelligence-actually-works
>
> **If you want to use the machinery:** the formula is in the figures link. Run it on a problem you know well and can check against a ground. Write down what would refute your result *before* you run it. The framework's own rule is that a loop cannot check the direction of its own question. A reported failure is more useful to me than a reported success.
>
> - [your name]
