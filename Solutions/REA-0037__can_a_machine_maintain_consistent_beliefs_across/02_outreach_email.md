# Outreach draft: check the separator before you decide about the theory

**Use:** one-to-one, or as a cover note attached to a submission through the public venues in `03_public_contact_points.csv`. **Not** for bulk send.

**Hard precondition:** the shape claim and its refuter must stay ahead of the links. If the theory is shown first, the recipient's verdict on the output is no longer independent (Fig 10 :42).

---

**Subject:** Check one distinction before deciding whether the claim is worth reading

> Hi [name],
>
> I have one specific output I would like you to check against what you already know. I am not asking you to read a theory first, and I am not asking you to agree with anything. If the output does not survive, there is nothing else to look at.
>
> **The output (`specified`, not `grounded`):** the phrase "consistent beliefs" names two different quantities. The first is internal coherence, no contradiction among the terms a system holds. The second is stable contact with something that does not change its answer because the system thinks so. The figures treat the first as cheap and evidentially empty: *"They are frame-internal. A frame cannot score itself with a quantity it also produces."* They treat the second as the only thing worth settling: *"An anchor is whatever settles the question and does not change its answer because of what any frame thinks."*
>
> The prediction is that a high self-consistency score and a lost channel to the ground can coexist, and that the drift is coherent, which is why nobody notices. In a long conversation the channel decays while the ground does not: *"the ground does not decay, the channel does."* When the evidence changes, a system that only adds terms accumulates a held belief alongside its contradiction, because a refusal is a different operator from an addition.
>
> **What I am not claiming:** that any named model does or does not do this, that a context length or a drift rate has been measured, or that the framework supplies a machine-specific threshold. The framework returns a shape, not a name, and this is a shape.
>
> **What would refute it:**
> 1. a system whose consistency report changes the anchor's answer, so the anchor updates on the frame;
> 2. a system with no refusal operator that nevertheless removes a held belief's standing to be composed over when the ground moves, where the removal is not just a new addition competing in a score;
> 3. a measurement in which the residual is genuinely global with no slot diverging;
> 4. a room chain with measured handoff fidelity and independent ground pressure that still cannot revise any belief.
>
> I wrote these down before sending this. If one holds, I withdraw the claim. A one-line "this fails because..." is more useful to me than agreement. If you would rather not engage, no reply is needed.
>
> **If it survives, and only then**, the sources are below. The figures are the authority, not my summary of them.
> - Verbatim figure text with line numbers (local extract): `FRAMEWORK/reference/03-FIGURES_TEXT.md`
> - Canonical usage rule (local copy): `FRAMEWORK/reference/FIGURES_README_canonical.md`
> - The eight-step loop: `FRAMEWORK/figures/THE_FORMULA.md`
> - Public repository with the SVGs: https://github.com/IsaiahN/tether/tree/general-agent/figures
>
> **If you want to use the machinery:** the formula is in the repository link. Run it on a problem you know well and can check against a ground. Write down what would refute your result *before* you run it, and state the mode of what you get. A reported failure is more useful to me than a reported success.

## Why this version is ordered this way

| the move | figure-grounded reason |
|---|---|
| Output first, theory second | Fig 10 :52 - *"Bring a characterised residual, never the source."* The recipient checks the distinction without holding the framework's interior. |
| Do not ask for agreement | Fig 2 :35 - *"Alignment is triangulation, not negotiation. A mirror cannot correct you."* |
| Pre-registered refuter | A falsifier written before the run is a design instrument. Written in `01` before the conclusion and repeated here. |
| Mode stated on every claim | `THE_FORMULA.md` - *"Mode. general · specified · grounded. State which."* |
| The two quantities kept apart | Fig 2 :34: coherent drift is the failure that nobody notices from inside. Merging them would recreate it in the email. |
| No architecture name | The framework returns a shape. Naming a model as the answer would be a binding from the engineering frame, provenance, not a derivation. |
| No request for trust or prestige | *"Prestige can fund an action. It can give an action a budget to be tried. But it cannot settle an action. Only the ground can settle it."* (*The Recursive Self-Improvement Trap*) |
| Offer the formula as a method to reuse | Fig 4 :22 - *"Only methods cross up. Only head starts come down."* |
| Ask recipients to state their own ground and refuter | `THE_FORMULA.md` "Direction": a frame cannot check the direction of its own question. |
| One-to-one, no bulk | Fig 2 :40 - agreement drawn from one evidence pool is one witness, not several. |

**Hard precondition:** this only works if the stage-1 output survives. The refuter is written to allow a genuine failure. Do not answer it for the recipient before they have replied.
