**Use:** one-to-one, or as a cover note attached to a submission through a public venue in `03_public_contact_points.csv`. **Not** for bulk send.

**Hard precondition:** this draft carries the differential-instrument claim and its refuter only. Do not append the figures, the essays or the framework before the recipient has recorded a verdict. Fig 10 :42: *"A verifier that can reconstruct the claim cannot verify it."*

**Subject:** A test-design claim that fails if two systems with the same score are not separable

> Hi [name],
>
> I have one specific output I would like you to check against what you already know about evaluation. I am not asking you to read any theory first, and I am not asking you to agree. If the output does not survive, there is nothing else to look at.
>
> **The problem, in effect terms.** A system that can acquire competence in a situation it was not prepared for and a system whose competence is confined to familiar tasks can produce the same benchmark score. That score therefore does not discriminate them. The residual is the missing discriminator, not the missing theory of intelligence.
>
> **The output (`specified`, not `grounded`).** A discriminating test must be a differential instrument with five properties:
>
> 1. Hold the system fixed and substitute the habitat, rather than adding more items from the same generator. A test harness is a substituted habitat, so a solve inside one proves the wiring of that habitat and never capability beyond it.
> 2. Report the prediction error per task slot and its trend, never only a mean. A global residual near zero with one live slot is a legal state, and averaging is how the live signal disappears.
> 3. Carry a dated exposure record. A passed item that was present in training is an import, not a derivation, even though the two look identical in the result.
> 4. Use an anchor that neither the system nor the test designer can move. Human approval is the right anchor for "is this a good answer for a person"; it is only an instrument for "is this code correct," and instruments can be wrong on axes they do not measure.
> 5. Separate "not found at this budget" from "not reachable," by distributing independent searchers before declaring absence. A failed novel task is not proof that a capability is missing.
>
> What this is **not** claiming: that any named system is or is not generally capable; that a single number can rank generality; that adding tasks to a benchmark measures anything beyond the task family; or that a human panel is the ground. It returns a shape, that is, a set of constraints on what a discriminating observation would have to look like. It does not return a verdict about a particular model.
>
> **What would refute it, written before this message:**
> 1. An agent-only change, with no change in contact, moves the ground reading across substituted habitats.
> 2. Per-slot residuals are a deterministic function of the aggregate score for every system tested, so averaging loses no information.
> 3. Repeated search inside a declared closed set adds a new atom with recorded provenance.
> 4. A complete, independently audited training ledger shows exposure status never changes the residual for any system tested.
> 5. A verifier that can reconstruct the held-out items returns the same verdict as one that cannot, across independent anchors.
> 6. A system reaches ceiling on substituted habitats while showing no vocabulary/objective link on multiple probes.
>
> I wrote these down before writing the rest of this. If one holds, the claim is wrong and I will retract it. A one-line "this fails because..." is more useful to me than agreement. If you would rather not engage, no reply is needed.
>
> **If it survives, and only then:** here are the source links. The figures are the authority, not my summary of them.
> - Verbatim figure text with line numbers (local framework extract, path on request)
> - ARC Prize 2024 Technical Report: https://arxiv.org/abs/2412.04604
> - On the Measure of Intelligence: https://arxiv.org/abs/1911.01547
>
> **If you want to use the method:** write down what a discriminating observation would look like before you run it, state the mode of what you get, and write your own refuter. A reported failure is more useful to me than a reported success.

## The two-stage offer, stated plainly

1. **Stage 1:** send the residual, the five properties, and the six refuters. Ask only: what would you count as a failure here? Record that answer before sending anything else.
2. **Stage 2, opt-in only:** if the recipient is curious, offer the figure extract and the two world papers. The figures, not the summary, are the authority.
3. **Stage 3:** offer the method for reuse, with the instruction that each user supplies their own ground and their own pre-written refuter.

A stage-1 reply is a conversation about test design, never corroboration. Do not pool later agreement as evidence (Fig 2 :40).
