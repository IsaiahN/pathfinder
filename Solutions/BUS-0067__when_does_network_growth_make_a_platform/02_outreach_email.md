**Subject:** Check one separation before you decide whether the framework is worth reading

> Hi [name],
>
> I am working on a figure-grounded derivation of a question in platform strategy. I have one specific output I would like you to check against what you already know. I am not asking you to read the framework first, and I am not asking you to agree with it. If the output does not survive, there is nothing else to look at.
>
> **The question in effect terms.** Network size changes two different things: what a user gets from a platform, and how hard the platform is for a challenger to displace. These are different slots with different thresholds, so the derivation treats them as a union of two conditions, not one dial with two directions.
>
> **The output (`specified`, not `grounded`).** The framework's rule is that capability is a property of the agent and its habitat, never of the agent alone, and that an actor's valence is relative to the residual rather than carried as a property. Applied here:
>
> 1. Growth helps users where the added participants stay in contact with the user residual as regenerating contributors. The feedback is a cycle, and the sign of the loop decides whether it closes. The same added participant can be a benefactor for matching and a malfactor for attention, so the effect changes sign with the residual and cannot be read off a mean over users.
> 2. Growth entrenches an incumbent where the installed base forms a closure that a challenger can move only by importing from a frame whose closure differs. Size is a head start that makes the next search cheaper; it is not a generator and it does not prove the method transferred. A room that keeps handing itself the same users compounds agreement without adding ground evidence.
> 3. The framework returns a shape and a set of conditions, not a critical mass, tipping number, or winning platform design. That number is a declared `gap`, reported as unreachable at this budget rather than as silence.
>
> **What I am not claiming.** Not that network effects are proved by a size-value correlation, a correlation cannot choose the arrow. Not that lock-in is inevitable: the same literature that describes tipping records that scale benefits are often exhausted above a small critical mass, so multiple networks can coexist. Not that data is automatically a moat; a moat claim needs provenance and a shadow test. Not that this is a theory of everything or a final answer. These are bindings from the business frame onto the vocabulary, recorded as such, with zero evidentiary weight until provenance is shown.
>
> **What would refute the shape:**
> 1. Per-user value keeps rising across a substitution that removes the added participants' contribution to contact.
> 2. Every added user strictly raises every existing user's value at all observed sizes, with no offsetting cost in any residual.
> 3. Adding users never changes subsequent adoption above an empirically observed critical mass, or a positive loop fails to close while the ground pays.
> 4. A challenger displaces a large incumbent purely by internal composition, with no new atom and no contact with a differing closure.
> 5. A platform's advantage survives removal of its head start while its method is held constant, or a head start alone produces new ground-verified value with no method.
> 6. A platform keeps the same closure for two periods and still produces new ground-verified readings without an import.
> 7. A single size lever raises usefulness and entrenchment across all regimes with no categorically different residue.
> 8. Exogenous variation in size produces no per-slot causal value change, or the association is fully reverse causation.
>
> I wrote these down before sending this. If any one holds, the shape is wrong and I will retract it. A one-line "this fails because..." is more useful to me than agreement. If you would rather not engage, no reply is needed.
>
> **If it survives, and only then:** the sources are below. The figures are the authority, not my summary of them.
> - Local verbatim figure text with line numbers: `FRAMEWORK/reference/03-FIGURES_TEXT.md` in this package.
> - Canonical figures README (public): https://github.com/IsaiahN/tether/blob/general-agent/figures/README.md
> - Figures and formula for direct download (SVG, branch `general-agent`): https://github.com/IsaiahN/tether/tree/general-agent/figures
>
> **If you want to use the machinery:** the formula is in the figures link. Run it on a platform problem you know well and can check against a market. Write down what would refute your result *before* you run it, and label the mode of what you get. The framework's own rule is that a loop cannot check the direction of its own question, and the architecture essay warns that outputs can be contrived to fit the formula. A reported failure is more useful to me than a reported success.
